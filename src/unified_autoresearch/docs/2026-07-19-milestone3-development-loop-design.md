# 里程碑三开发闭环设计

## 目标与边界

里程碑三只建立八个冻结开发流域、Maurer 气象驱动和两套冻结开发日期协议的数据准备、外部开发验证评分与四类轻量参考候选闭环。任何结果都只表示开发验证，不进入封存最终评估，也不支持超过基线的表述。

## 数据准入方案

比较了三种方案：

1. 直接打开包含完整历史的原始流域文件后按日期筛选。该方案可能在筛选前读到封存期，拒绝采用。
2. 只接受专门预切分、逐文件散列并明确声明日期边界的开发数据根。编排器先验证清单、文件集合、冻结流域、字段、日期和有限值，再生成候选训练包、候选预测包及隔离评分真值，采用此方案。
3. 永久只使用合成数据。它能验证代码边界，但不能形成真实开发结果，仅作为实现与反例测试手段。

在存在经过证明的真实开发专用数据根之前，不打开任何真实水文数据文件。第一轮只用合成数值验证数据边界。

## 隔离结构

每套开发协议生成三个互不混挂的目录：训练目录含气象、训练监督目标和静态属性；预测目录只含气象和静态属性；评分目录只含验证真值。候选预测运行不得挂载评分目录。

源数据根必须只有清单声明的三个普通、非链接文件以及源清单本身。源清单日期范围必须精确为 1999-10-01 至 2008-09-30，且声明不含封存最终评估。实际表格还必须与八个冻结流域、五项气象变量、27 项批准静态属性和唯一“流域—日期”键完全一致，全部数值有限。

## 检验方式

- 反例在打开源表前拒绝越界日期声明。
- 预测包机械检查不含观测流量或验证真值。
- 漂移流域选择、额外静态字段、非有限值、重复键、未声明文件和链接文件均须拒绝且不生成最终输出根。
- 每轮完整测试、源代码、配置、依赖、Git 原始状态和运行证据组成不可覆盖数字指纹，并建立操作系统拒绝写入的审核快照。
- 两个没有实现历史的全新上下文分别完成方法审核和原始证据复验。任一失败均保留本轮证据并进入新修复根。

## 外部开发验证评分

评分器只接受数据准备器生成且全文件集合与散列仍一致的开发数据包，不接受任意真值路径。调用者必须提供在数据包外部冻结并进入登记或数字指纹的预期数据包清单散列；评分器在解析清单前先核对原始清单字节。它从所选协议的隔离评分目录读取验证真值，从候选运行产物读取预测，并要求两者的“流域—日期”键集合逐项相等、无重复、数值有限且每个流域的真值方差非零；任何缺行、额外日期、错误流域、重复键、非有限值、布尔预测、链接预测或数据包篡改都必须在评分结果文件创建前拒绝。

每个协议输出八个流域的 Nash–Sutcliffe 效率系数、候选标识、候选类别、已登记运行标识、冻结数据包清单散列及输入文件散列。候选汇总器只接受字段精确、候选身份一致、分别绑定给定运行且来自同一冻结数据包的forward和reverse报告，为每个候选生成八个“候选—流域”单元。极端有限指标使用先分别除以二再相加的方式避免平均值溢出；所有可扩展JavaScript对象表示法内容先在内存完成有限性检查和序列化，再排他创建结果文件，失败不得留下部分文件。它只汇总开发验证，不调用公平基准评分程序，也不产生胜出或超过基线结论。

## 资源判断

数据边界单元测试和小型合成表属于轻量任务，不启用独立监督程序。后续候选运行按实际数据量和小规模实测确认内存余量；只有被判定为重型的任务才必须先启用独立资源监督。
