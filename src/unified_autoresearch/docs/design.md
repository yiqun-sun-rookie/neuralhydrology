# 统一自动研究纵向最小版本设计

## 结论

采用“独立编排层复用现有能力”的方案：所有新增实现、协议、测试和证据均位于
`src/unified_autoresearch/`，现有 `src/fair_benchmark/`、`neuralhydrology/`、
`src/hydroagent/` 只作为只读依赖。该方案既保护当前脏工作区，又能在不预设模型菜单的前提下，
用同一个候选协议接入任意命令行候选。

## 备选方案与取舍

1. 直接扩展 `src/fair_benchmark/`：复用最多，但会修改现有基准实现，并与“新增实现限定在新目录”冲突。
2. 新建独立编排层并复用现有只读组件：隔离清晰，可逐步接通四类入口，选用此方案。
3. 建立完整容器服务：操作系统隔离最强，但当前 Windows 本地环境的容器、数据挂载和图形处理器配置会扩大范围，
   不适合作为纵向最小版本。

## 系统边界

- 不运行 `src/fair_benchmark/score.py`，不读取最终评估答案文件，不生成 1989-10-01 至
  1999-09-30 的指标。
- 数据准备器只生成两个已批准开发协议的数据包。候选预测阶段不挂载验证真值；评分器在候选退出后独立读取真值。
- 候选只看 Maurer 气象驱动、27 项静态属性及训练阶段监督目标。预测输入不得含观测流量、流量衍生属性或模型结果。
- 候选方法不设菜单。`category` 只用于证明深度学习、概念降雨—径流、融合和自定义 Python 四种入口均可运行，
  不限制后续候选的内部结构、框架或优化方法。

## 结构

```text
src/unified_autoresearch/
├── protocols/       冻结的数据、候选和资源协议
├── selection/       仅用静态属性冻结八个开发流域
├── registry/        追加式候选、状态、实验和数字指纹
├── runtime/         单调度锁、受限执行、文件访问记录和资源监督
├── adapters/        四类入口共用的命令候选适配器
├── candidates/      四个纵向验证参考候选
├── evaluation/      双验证评分、比较和继承选择
├── tests/           单元、反向、恢复和端到端测试
└── evidence/        进度、审核判定和可复现证据
```

## 数据流

1. 流域选择器读取冻结的 531 流域清单和 27 项静态属性，按确定性最远点覆盖法选择八个流域。
   选择文件一经产生不可覆盖，其清单和输入数字指纹进入协议。
2. 数据准备器在候选运行前生成按流域、按开发协议隔离的数据包。训练包含气象、静态属性和监督目标；
   预测包只含气象和静态属性；验证真值只供外部评分器读取。
3. 候选描述声明入口命令、依赖、输入、输出、资源、检查点、恢复和随机种子。调度器持有唯一文件锁，
   通过追加事件完成原子状态转换。
4. 受限运行器使用 Python 运行时审核钩子执行候选：允许文件清单之外的打开操作默认拒绝并记录；
   子进程、动态本地库和网络默认禁用。故意读取禁用文件的反向候选必须以非零退出码失败。
5. 外部评分器检查预测行、日期、有限值和 Nash–Sutcliffe 效率系数（衡量预测与观测吻合程度），
   生成每个“类别—流域”在两个开发协议上的结果，并按冻结规则汇总为 32 个单元。
6. 比较器只在开发验证上决定是否继承候选，不得调用最终评估服务。本轮所有结论均标记为开发验证结果。

## 不可覆盖登记与数字指纹

- 使用 SQLite 数据库事务提供原子追加；数据库触发器拒绝更新和删除候选、事件、实验和指纹记录。
- 当前状态由事件序列计算，不在原记录上修改。更正记录必须填写 `corrects_id`，并保留旧记录。
- 单一调度锁使用原子创建的锁文件，锁内记录进程编号、创建时间、程序路径和唯一运行标识。
- 每个候选实验的 256 位安全散列数字指纹覆盖：当前提交、未提交差异、源码清单、配置、依赖清单、
  数据清单、随机种子和产物清单。各部分散列再组成根散列。

## 中断恢复和资源安全

- 协议要求每个阶段或每 15 分钟写一次原子检查点，校验后只保留最近两个版本。
- 受控中断通过调度器创建停止请求完成；候选在下一安全点保存并以约定退出状态结束，恢复运行必须引用该检查点。
- 每项任务在启动前声明峰值内存、输出容量和针对该任务的安全余量，再与启动时实际可用内存和磁盘比较；
  无法覆盖估计和余量时必须缩小任务或不启动，不使用统一容量门槛。
- 是否启用独立监督程序及其采样、汇总间隔由任务规模、时长和波动性决定，并记录理由。需要监督但监督程序
  尚未启用时不得启动；监督程序只管理自己创建且核验归属的进程。

## 验证

- 修改行为前必须先看到对应自动测试因缺少该行为而失败。
- 每类候选均执行一次受控中断恢复和一次干净重跑；随后连续执行两次完整纵向运行。
- 完整运行的机械门槛：退出码为零、32 个结果单元齐全、所有指标有限、禁止读取次数为零、登记校验失败为零。
- 每个里程碑的实现审核和定向复验由两个没有实现对话记录的独立任务完成，审核目录只读并绑定同一源码数字指纹。
- 最终另做数据与代码、干净重跑、对抗性检查三次独立审核；任何一次都不能把开发结果表述为超过基线。
