# 里程碑二受限候选运行环境设计

## 结论

使用固定的 Python 启动器执行候选入口，在候选代码运行前安装审核钩子。候选描述、隔离目录、文件访问、
依赖导入、网络、子进程、检查点和退出状态均由编排层验证。该方案与现有设计一致，能够用真实文件打开和
真实子进程反例机械验证，同时不需要启动训练任务。

## 方案比较

1. **固定 Python 启动器和审核钩子：采用。** 可以在 Windows 和 Linux 上复用，能在打开文件前拒绝并留下记录，
   也能阻止候选自行启动子进程、网络连接和动态加载本地库。
2. **操作系统沙箱或容器：暂不采用。** 隔离强度更高，但当前 Windows 环境没有已冻结的容器或应用容器配置，
   引入后无法在现有测试中低成本独立复验。
3. **只复制允许输入并在运行后扫描：拒绝。** 它可以减少误用，但不能证明候选没有读取工作区中的其他文件。

## 组件和数据流

- `runtime/descriptor.py` 严格校验候选描述。未知字段、缺少入口、非精确依赖版本、越界相对路径或不一致的
  检查点声明均拒绝。
- `runtime/layout.py` 排他创建一次性运行根，分别建立只读候选源码、只读输入、输出、检查点暂存和日志目录；
  已存在的根不允许复用。
- `runtime/adapter.py` 只构造固定启动器命令，不执行候选提供的任意壳层命令。训练和预测入口都是候选根内的
  Python 文件。
- `runtime/bootstrap.py` 在候选代码前安装审核钩子。允许清单外的文件打开默认拒绝；子进程、网络和动态本地库
  默认拒绝。审核记录通过预先打开的文件描述符追加，拒绝事件也必须落盘。
- `runtime/checkpoints.py` 只接受候选暂存目录中的完整检查点，由父进程验证清单后原子提升为不可覆盖版本。
  受控停止退出状态只有在检查点提升成功时才有效，恢复必须引用已登记的检查点。
- `runtime/runner.py` 组合上述组件，生成结构化运行结果并将每次运行绑定到唯一运行标识和唯一输出根。
- `runtime/orchestrator.py` 负责运行级登记和证据编排，不把数据库职责放入候选子进程。每个排他运行根只接受一个
  空登记库和一个运行标识；编排器先追加候选、实验、已登记、已验证和已排队状态，再持有登记指定的真实调度锁进入运行。
  候选结束后，编排器为真实输出、全部日志和检查点生成八部分最终数字指纹，然后追加成功、失败或已保存检查点状态。
  启动前异常也必须写结构化编排日志、最终数字指纹和失败状态，并保留原异常。
- `runtime/resources.py` 使用候选声明的实际峰值估计、任务专属安全余量和启动时容量决定是否运行；旧的统一
  容量门槛不再用于新运行。需要独立监督但监督程序尚未启用的任务在本里程碑直接拒绝启动。

预测运行只挂载 `predict_features.parquet`、`static_attributes.json` 和选定模型产物；验证真值不出现在预测运行目录。

## 错误处理

- 候选描述或运行布局不合法：退出状态 2，候选不启动。
- 禁止访问、网络、子进程、动态库或未知依赖：启动器记录拒绝事件并以退出状态 2 结束。
- 候选自身异常或未知退出状态：记录为运行失败，标准化为退出状态 1。
- 受控停止且检查点完整：退出状态 75；检查点缺失或不完整则视为运行失败。
- 任何最终运行根、检查点版本或证据根已存在时均拒绝覆盖。

## 可验证边界

本里程碑验证 Python 候选的真实运行时约束，不把审核钩子表述为抵御恶意本地管理员或任意本地原生扩展的
操作系统安全边界。预测真值不挂载、非声明依赖不导入、动态加载本地库被拒绝，以缩小该限制。

通过门槛：完整测试、反向候选、受控停止恢复、证据清单和登记验证全部通过，再由两个没有实现对话记录的
全新任务分别完整审核和定向复验。
