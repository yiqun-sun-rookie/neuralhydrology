# 里程碑四第 5 条：扩至 64 与 531 流域前的剩余工作清单（2026-07-25）

以 8 流域真实监督循环的实测数为锚点，列出扩到 64、531 流域前必须完成的事项与需要拍板的决定。
这是剩余工作清单，不是承诺的性能数字；参考候选是入口证明、非真实模型，真实候选的计算量由候选本身决定。

## 一、8 流域实测锚点（v3 监督循环）

| 项 | 实测值 |
|---|---|
| 每次循环产物 | 12 兆字节 / 526 个文件（16 个已登记运行 + 评分 + 汇总 + 监督日志） |
| 数据包 | 1.4 兆字节（8 流域两协议） |
| 数据源根 | 629 千字节 |
| 候选实际计算时间 | 约 78 秒（16 个参考候选串行，采样 311 条 @0.25 秒） |
| 单候选进程峰值内存 | 0.138 吉字节，串行执行 |
| 启动可用内存余量 | 约 5 吉字节，v3 近-耗尽下限 1.5 吉字节 |

倍数：64 流域 = ×8，531 流域 = ×66.4。

## 二、存储估算（线性外推，非约束项）

- 数据包随流域数线性：64 约 11 兆字节，531 约 93 兆字节。
- 循环产物 = 每运行固定开销（候选源码拷贝、登记、日志，与流域数无关）+ 随流域数线性的数据/预测部分。
  粗估每次循环：64 流域约 30–50 兆字节，531 流域约 150–250 兆字节。
- 当前可用磁盘 2158 吉字节，**存储不构成约束**。

## 三、时间估算

- 每运行的框架固定开销（布局拷贝、监督启停、评分、登记、指纹）与流域数弱相关。
- 候选计算随流域数 × 时间步线性。参考候选：531 流域串行约 87 分钟；**真实候选由模型本身主导，需按具体候选另估**。
- 结论：**串行在 531 流域不可接受**，需并行（见第五节）。

## 四、数据准备（必做，尚未做）

1. 用 `data/real_source.py` 为 64 与 531 的**冻结流域集**构建真实开发源与两协议数据包（当前仅 8 流域）。
2. 逐流域复核：日期边界、封存区间命中 0、预测包不含观测流量、单位换算（×86.4 / 面积）无误。
3. 静态属性表须与冻结流域选择同源、散列钉死；确认 64/531 流域 27 项属性无缺失。
4. 注意两个敏感流域：06847900（验证期流量标准差极小）、08190500（大量零流量日），判定规则不能只看中位数。

## 五、并行与聚合资源门槛（必做的设计项）

- 当前候选**串行**执行，v3 启动门槛是**按单任务**判断。
- 并行执行时，启动门槛必须改为**聚合**：并发候选的峰值内存之和 + 各自余量 ≤ 当前可用；核心/图形处理器同理。
- 每个运行一个监督子进程；并行时 N 个监督并发，需确认监督自身开销与日志量。
- **需要拍板**：并行度取多少、聚合门槛的具体规则。

## 六、监督在真实规模下的未知项（必做的验证）

- 演示候选峰值仅约 0.14 吉字节、单次数秒。**真实训练规模、长时、图形处理器、并行任务下监督行为未验证**。
- 采样间隔 0.25 秒对长时真实运行会产生大日志，可能需按任务调粗；协议里的**汇总间隔尚未实现**。
- 峰值估算方法（v3 承载）需一个**真实重候选的代表性小试验**来标定，当前只有轻候选两个一致标定点（0.1374、0.1376）。
