# 阶段3 修正案 01a：单任务数值崩溃的处置规则（2026-08-18，汇总前冻结）

上游预登记：`2026-08-18-online-noise-stage3-camels-real-observation-prereg-v01.md`。
本修正案在 **summarize 尚未运行、任何 R1/R2/R3 数字尚未产生**时写下。

## 事实

首轮 `run`（2340 任务）在第 2036 个任务处中止：流域 03384450、P 臂、格 m=10/c=0，
`sigma_filter.sigma_points` 抛出"协方差非半正定，最小特征值 −3.58e-08"。这是数值级
违反（量级 1e-8），发生在最高地下水噪声乘子 × 真实观测的组合上。已保存的 2035 个
输出全部完整（原子写保证）；其余 304 个缺失任务是进程池中止后未被执行的，
不是失败（集中在尚未开始的 m10_c0.2 / m10_c0.4 两列）。

预登记 §5 写了"任何运行失败 → 只报差异，不解释新结果"，但没有规定**部分任务
数值崩溃**时其余任务与汇总如何处置。本修正案补上这条，规则如下。

## 规则（在看到任何汇总数字之前冻结）

1. **不改滤波内部**。不加抖动、不夹特征值、不调 UT 参数——那会改变与阶段1/2
   逐位一致的冻结构造。崩溃照崩，记录在案。
2. **runner 改为逐任务容错**（纯基础设施：try/except 记录 status=failed 与异常文本，
   不再让单任务异常中止整个池）。数值路径零改动。
   失败清单写入 `verification/run_failures.json`。
3. **计分规则（只会更严不会更松）**：
   - 某流域某臂只要有 ≥1 个格崩溃 → 该流域该臂的 A2f99 混合无法按定义构成 →
     该流域该臂 **R1 记为数值坍缩失败**（计入 R1 通过率分母）；
   - 该流域该臂退出 R2 配对（无预报可比）；若崩的是 CTRL 臂，该流域从两臂的
     R2 配对中一并退出。退出计数必须在汇总中披露；
   - R2 的 n 因此可能小于 52，按实际配对数报告，不填补、不插值。
4. **不重试、不换参数重跑崩溃任务**。断点续跑只补"未执行"的任务；
   已崩溃的任务重跑一次（因为进程池中止导致其后任务未执行，需要一次完整补扫），
   若再次崩溃即定格为失败——同一确定性代码路径下预期结果相同。
5. 若崩溃面扩大到影响 R1 门本身（某臂 >20% 流域崩溃），这本身就是 R1 门失败的
   如实结果，按预登记报告并停，不做任何补救。

## 与预登记 §5 的关系

§5 的"任何运行失败 → 只报差异"针对的是**冻结输入或复现身份不符**类失败；
数值崩溃是 R1 声称边界内的实验结果（稳健运行门测的就是这个），按上面第 3 条计分
比按 §5 直接中止更严格也更诚实。本修正案不触碰任何门槛数字、判据方向或准入集。
