# 历史连续多尺度气象模型版本09冻结经典基准信息边界审核

## 结论

当前唯一正式评分计划为`HOLD`。冻结八随机数经典长短期记忆网络集成不满足其赛道规范声明的
“相同预测信息”条件：旧训练代码把训练起点前269天的可用气象和流量一起放入归一化统计，并把
可用流量放入每流域损失尺度。该区间是`1999-01-05`至`1999-09-30`，完全位于正式评估期。

正式评分服务使用的531流域冻结基准向量与该旧集成结果逐字节相同。因此，在不修改受保护评分服务和
冻结目录的现状下，即使以后唯一评分返回`PASS`、`HOLD`或`REJECT`，也不能把它解释为满足相同信息
规则的正式胜负。

本次没有打开正式评估观测、旧测试结果对象或流量原始文件，没有生成正式输入、训练、预测或评分，
也没有修改科学协议配置、受保护冻结目录或评分代码。

## 1. 冻结赛道明确禁止测试期统计

`src/fair_benchmark/frozen/track0_forcing_only.spec.yaml`明确规定：

- 训练期为`1999-10-01`至`2008-09-30`；
- 正式评估期为`1989-10-01`至`1999-09-30`；
- 禁止正式评估期观测流量；
- 禁止测试期或全数据集统计。

这不是事后新增标准，而是已确认的冻结赛道规范。正式版本09本身也固定动态变量、训练目标和每流域
损失尺度只能使用训练期统计。

## 3. 旧核心如何把正式评估期带入训练统计

权威代码对象为：

`1f9804e359283f1963bcf0aa9ffab213538c16e8`

只读命令：

```powershell
git show 1f9804e359283f1963bcf0aa9ffab213538c16e8:neuralhydrology/datasetzoo/basedataset.py
git show 1f9804e359283f1963bcf0aa9ffab213538c16e8:neuralhydrology/training/loss.py
```

证据链如下：

1. `basedataset.py`第454至468行用
   `seq_length - predict_last_n = 270 - 1 = 269`天计算预热起点，并读取预热起点至训练终点；
2. 第518至531行把整个数据框，包括目标流量，转换并拼接为训练用`xarray.Dataset`；
3. 第556至566行直接在该完整对象上计算每流域目标标准差；
4. 第790至826行先计算每流域标准差，再对完整对象计算所有特征的中心和尺度；
5. 第614至625行只在非训练模式屏蔽区间外目标；训练模式没有把预热期目标设为空值；
6. `loss.py`第217至257行证明每流域目标标准差通过
   `1 / (per_basin_target_stds + 0.1) ** 2`影响每个训练样本的损失权重。

因此，预热期气象虽然是首批训练样本所需的合法因果输入，但预热期统计不属于训练期统计；预热期流量
既不是允许输入，也不应参与目标归一化或损失权重。

## 4. 暴露范围

日期算术固定为：

- 预热起点：`1999-01-05`；
- 预热终点：`1999-09-30`；
- 日数：269；
- 每流域加载期：3,557天，其中训练目标期3,288天；
- 若全部位置均非空，预热期占加载统计的`7.562553%`；
- 269天占完整3,652天正式评估期的`7.365827%`；
- 531个流域最多对应142,839个正式评估期流域日位置。

本次为保持正式评估答案封存，没有读取这些位置的观测值。因此，实际非空流域日数量以及泄漏对
`0.759225`中位纳什－萨特克利夫效率系数的方向和大小目前无法确定。

`results/18_lstm_fair_531/_reports/ensemble_cudalstm_maurer_8seed_per_basin.csv`

正式评分冻结基准文件：

`src/fair_benchmark/frozen/track0_forcing_only_baseline_per_basin_nse.csv`

二者均有531行数据，且字节SHA-256完全相同：

`63d989d155f6806d52f996e28f734afb9ec7cecbdcc797ac414d3cd2ff8670d6`

`src/fair_benchmark/score.py`读取该冻结向量作为基准，并只对挑战者源码执行禁止访问扫描；它不会审核
基准训练时的信息来源。因此，未来评分前置门若只检查挑战者，不会发现这一基准侧违规。

## 6. 可支持、不可支持和未知的结论

### 事实

- 旧训练代码访问并把预热区间中的可用正式评估期流量纳入目标统计和损失尺度；
- 冻结评分向量直接来自这八个旧运行；
- 正式版本09计划使用训练期统计，不会复制这一信息；
- 当前比较双方的信息集合不相同。

### 不能支持

- 不能把旧基准描述为符合冻结赛道相同信息规则；
- 不能把相对该基准的评分结果称为正式公平胜负；
- 不能把该基准称为必然更强的“保守基准”，因为泄漏影响方向未知；
- 不能在失败时据此否定长期气象历史，在通过时据此声称同信息显著优越。

### 未知

- 269天中实际参与统计的非空流量数量；
- 清洁重训的八随机数经典集成正式分数；
- 旧统计与清洁统计造成的逐流域和总体分数差；
- 连续历史候选在合法同信息基准下是否通过预注册门。

## 7. 停止条件与推荐修复

在用户选择修复路线前：

- 不申请正式输入生成、严格嵌套、主训练、正式预测或评分授权；
- 不调用正式评分服务；
- 不修改`src/fair_benchmark/frozen/`或`src/fair_benchmark/score.py`；
- 不把现有唯一评分计划标记为可执行。

推荐新建一个不覆盖现有冻结赛道的清洁同信息赛道，由封存服务在同一次调用中同时接收清洁经典集成和
连续历史候选预测，使用同一答案、同一流域和同一门槛计算配对结果。该路线需要新的用户授权、新的赛道
标识和新的独立审核设计；它不能伪装成现有冻结赛道的无变化延续。

备选路线是保留旧基准仅作历史参考，并明确放弃“相同信息正式胜负”主张。直接修改现有冻结基准或在
现有评分服务上继续宣称公平胜负均不推荐。
