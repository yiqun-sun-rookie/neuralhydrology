# 历史连续多尺度气象模型版本09经典训练对齐审查

## 结论

正式版本09可以严格证明两件事：

1. 八个冻结经典检查点在相同位置输入张量上的函数映射，可由版本09干净经典近期路径和停用历史路径
   逐元素复现；
2. 新正式管线中的干净经典路径与停用历史路径，可在相同输入、批次、随机数、损失和优化器合同下
   进行30轮逐更新零差异嵌套验证。

正式版本09不能、也不得声称逐步重现旧八随机数训练轨迹。旧训练在计算流量归一化和损失尺度时包含
训练起点前269天，其中`1999-01-05`至`1999-09-30`属于正式评估期；旧批次排列、完整运行环境和
气象源字节也没有封存。复制旧流量统计会违反正式评估观测封存，猜测旧随机数或软件后端不能形成证据。

本次审查发现并在实施计划中修正两项正式输入语义偏差：

- 27项静态属性必须按名字母顺序送入模型，而不是按配置文件列出顺序；
- 静态属性尺度必须用样本标准差`ddof=1`，而不是总体标准差`ddof=0`。
- 静态属性必须在源双精度中计算统计和归一化，最后才转为单精度模型输入。

当前仍为`NO-GO`：正式输入、训练、正式预测和评分均未授权，正式结果目录不存在。本次只修改计划和
审查文档，没有生成数据、训练、预测、读取正式评估观测或调用评分服务。

## 3. 旧训练轨迹不可合法重建

旧核心数据集提交的实际顺序为：

1. 对270天序列和`predict_last_n=1`计算269天预热偏移；
2. 将每个训练时间片从`start_date - 269天`载入；
3. 在构建训练查找表前，对整个载入数据集计算每流域原始流量标准差；
4. 同样对整个载入数据集计算气象和流量的中心与尺度；
5. 完成归一化后才构建训练样本查找表。

因此，配置训练起点`1999-10-01`对应的数据统计起点是`1999-01-05`。旧代码没有在统计前把这269天
的流量置空。旧归一化文件中的流量中心和尺度分别为`1.5118002891540527`和
`3.629760980606079`，但这些数值不能进入版本09正式训练，因为它们聚合了正式评估期观测。

当前Maurer源对旧统计区间的只读重算比只用训练期更接近旧气象统计，但仍不能逐值复现；旧运行没有
保存531份气象源文件哈希，所以无法区分源文件变化、读取差异或环境差异。该结果只能支持“旧统计包含
预热区间”的代码结论，不能支持“当前源就是旧源”的结论。

旧批次与随机数也不可重建：

- 数据加载器使用`shuffle=True`、4个工作进程且没有显式生成器；
- Python、NumPy、PyTorch中央处理器和图形处理器都只设置同一个全局种子；
- 模型构造、数据加载器、工作进程和丢弃层共享或派生自未封存的随机数状态；
- 旧产物没有逐轮排列、工作进程种子、逐步随机数状态或逐步参数；
- 旧运行要求只限定`torch>=2.0.0`，没有保存实际Python、PyTorch、CUDA、cuDNN和驱动版本；
- 旧优化器工厂只传入学习率，其余Adam参数和实现后端由当时PyTorch默认值决定。

版本09必须把这些因素作为新合同显式冻结，而不是宣称恢复旧轨迹。

## 4. 静态属性语义修正

旧配置和冻结静态逗号分隔文件都按业务顺序列出27项属性，但旧核心数据集读取后执行
`df.sort_index(axis=1)`，随后才计算统计和生成张量。旧模型实际接收的顺序是：

```text
area_gages2, aridity, carbonate_rocks_frac, clay_frac, elev_mean,
frac_forest, frac_snow, geol_permeability, gvf_diff, gvf_max,
high_prec_dur, high_prec_freq, lai_diff, lai_max, low_prec_dur,
low_prec_freq, max_water_content, p_mean, p_seasonality, pet_mean,
sand_frac, silt_frac, slope_mean, soil_conductivity,
soil_depth_pelletier, soil_depth_statsgo, soil_porosity
```

冻结531流域静态文件的只读重算结果：

- 逐属性均值对旧归一化文件最大绝对差：pandas重算`1.14e-13`，独立求和顺序复核
  `4.55e-13`；
- `ddof=1`逐属性标准差对旧归一化文件最大绝对差：`5.68e-14`；
- 如果误用`ddof=0`，`elev_mean`尺度会从`787.773498670254`变为
  `787.031366146903`，绝对差`0.742132523350506`。

旧核心在pandas双精度数据框上完成静态统计和归一化，随后才调用`astype(np.float32)`。如果按原
版本09计划先把原始静态值转成`float32`，再转回双精度计算统计，则14,337个归一化静态值中有
8,421个与旧精度顺序的单精度结果位不同，最大绝对差`8.344650268554688e-7`。若连归一化也在
单精度中执行，则有10,560个值不同，最大绝对差`1.430511474609375e-6`。

用冻结静态源、显式字母列顺序、源双精度均值和`ddof=1`尺度得到的预归一化`float32`有效载荷
SHA-256为`aa53d1d06247b246f5557efe6761b9b7becd2be3a680f99d667d2e3c89b9b37a`。
直接使用旧归一化文件中保存的静态均值和尺度独立重算，得到完全相同的14,337个单精度值和同一哈希。

版本09输入计划因此固定：

- 先按`data.py::STATIC_COLUMNS`验证冻结源文件表头，保证源文件身份；
- 再按显式`FORMAL_V09_STATIC_COLUMNS`字母顺序写`statics.npy`；
- 静态中心使用531流域均值，静态尺度使用`ddof=1`；
- 同时封存字母顺序的`statics_raw.float64.npy`和预归一化`statics.npy`；
- 静态精度顺序固定为源双精度统计、双精度归一化、最后转单精度；
- 清单、归一化文件和审核报告逐项记录列名、顺序和自由度；
- 任何训练读取器只接受预归一化数组，不能重新按配置顺序排列或再次归一化。

动态输入顺序仍按旧配置的五项Maurer顺序。旧输入层按配置列表拼接动态字段，这一部分没有发现语义
顺序偏差。

## 5. 新干净训练合同

版本09的`B09-CLASSIC`定义为“经典结构、合法训练期统计、显式可复现训练程序”的控制，而不是旧模型
重新训练。固定差异如下：

| 项目 | 旧训练 | 版本09正式训练 |
|---|---|---|
| 流量统计 | 含269天预热区间 | 只用1999-10-01至2008-09-30 |
| 气象统计 | 含269天预热区间 | 只用训练期 |
| 静态顺序 | 核心运行时字母排序 | 显式冻结同一字母顺序 |
| 静态尺度 | pandas样本标准差，`ddof=1` | 显式`ddof=1` |
| 静态精度 | 双精度统计和归一化后转单精度 | 封存同一精度顺序的预归一化数组 |
| 批次排列 | 全局随机数、未封存 | 独立CPU生成器、逐轮哈希 |
| Adam | 仅传学习率，后端随环境 | 全参数与后端显式冻结 |
| 环境 | 未封存 | Python、PyTorch、CUDA、cuDNN、驱动和确定性开关封存 |

版本09Adam固定为`betas=(0.9,0.999)`、`eps=1e-8`、`weight_decay=0`、
`amsgrad=False`、`maximize=False`、`foreach=False`、`fused=False`、
`capturable=False`和`differentiable=False`。三个模型家族和严格嵌套必须使用完全相同的环境字段、
训练键、逐轮排列、学习率、损失和优化器设置。

批次数字顺序也已冻结：气象和目标统计以双精度封存，但中心、尺度、原始批次和每流域损失尺度在
正式批次运算中均为单精度；中央处理器NumPy按减法后除法归一化，随后才传入设备。连续历史候选先
归一化完整3,562天气象窗口，再聚合120个历史分箱；近期模型的270天输入必须与完整窗口末270天
逐字节一致。静态属性直接读取已按旧核心精度顺序预归一化的单精度封存，不再执行第二次归一化。

训练随机数分为三个明确作用域。模型参数仍用100至800初始化；每轮排列使用
`seed * 1_000_003 + epoch`的独立中央处理器生成器；模型和Adam构造后，PyTorch中央处理器与
图形处理器丢弃流统一重置为`seed * 1_000_003 + 900_001`。否则369隐藏单元控制因初始化消耗
更多随机数，会在同一名义随机数下从不同丢弃流位置开始。三个模型族必须记录相同的初始丢弃状态
哈希；经典与连续历史候选还必须保持相同的近期丢弃流。

显存资源预检不能复用正式模型。完整前向、反向和Adam步会改变参数、优化器状态和丢弃流，所以预检
必须在独立一次性子进程中使用合成数据和可丢弃模型；该进程完全退出后，正式训练由新进程从验证、
构造和播种重新开始。

## 6. 停止条件与继续条件

正式输入阶段必须在下列任一情况停止：

- 静态源表头不等于冻结27项业务顺序；
- 正式静态数组列名不等于显式字母顺序；
- 静态尺度未标记或未使用`ddof=1`；
- 原始静态值在统计前转为单精度、预归一化有效载荷哈希漂移或训练再次归一化；
- 旧检查点真实语义桥接没有覆盖531乘12个冻结训练键或任一最大差不为0；
- 动态、全局流量或每流域流量统计读取了训练期以外的日期；
- 旧动态或流量归一化文件被正式输入构建器或训练器读取；
- 任何正式评估期流量字段被解析、转换、汇总、哈希或记录；
- 输入、协议、授权、环境或源摘要发生漂移。

严格嵌套和主训练还必须在下列任一情况停止：

- Adam任一显式参数或后端与封存不一致；
- 严格嵌套任一步不满足绝对0、相对0；
- 正式环境字段在严格嵌套与24次主训练之间变化；
- 为贴近旧轨迹而更换批次生成器、归一化范围、随机数流或软件版本；
- 丢弃流没有在模型和优化器构造后按独立派生种子重置，或三个模型族初始状态哈希不同；
- 显存预检与正式训练共用进程、模型、Adam、随机数状态或正式输入；
- 完整气象窗口在历史分箱后才归一化、近期切片与完整窗口末270天不相同，或归一化转移到设备执行；
- 内存、显存、非有限值、状态诊断或既有封存门失败。

正式输入阶段改为两个不能合并的批准。首先只允许实现和合成测试：

```text
批准版本09正式输入代码实现与合成测试；不批准生成正式输入、训练、正式预测或评分。
```

代码提交、完整测试和独立审核通过后，才另行请求：

```text
批准版本09正式输入生成阶段；不批准训练、正式预测或评分。
```

第二个批准只允许一次真实输入生成；严格嵌套、24次主训练、正式预测和唯一评分仍分别需要新的单独
授权。
