# 历史连续多尺度气象模型版本09状态数值诊断预注册

## 结论

当前结论为`NO-GO`执行、`GO`补齐协议实施细节：

- 版本08的历史记忆状态范数偏大是真实、跨训练随机数重复出现的数值警示；
- 现有证据同时表明全部历史状态有限，没有训练失败、非有限预测或预注册门槛违规；
- 版本09保持已通过内部筛选的模型、遗忘门偏置、门控形式、训练轮数和成功条件不变；
- 在正式训练后、正式预测前，用独立进程对八个连续历史候选检查点执行冻结的状态分布诊断；
- 大而有限的状态、门饱和或与版本08数值不同只作强制报告，不能用于模型、随机数、检查点、
  集成权重或是否进入评分的选择；
- 非有限状态、梯度链路不成立、诊断重放不一致或诊断改变训练轨迹时，训练阶段固定为`HOLD`，
  不得进入正式预测。

本文件不授权生成531流域正式输入、训练、正式预测或评分，也不改变版本09科学协议JSON。

## 1. 已有事实

版本08独立审核从三个第30轮检查点重算了全部43,800个内部确认样本。这里的“原始历史记忆
状态范数”定义为：对每个样本的256维历史编码器最终记忆状态计算欧氏范数，再在样本之间汇总。
它不是历史门参数范数，不是近期路径隐藏状态范数，也不是性能指标。

| 训练随机数 | 原始历史记忆状态范数中位数 | 95%分位 | 最大值 | 门控后记忆状态范数中位数 |
|---:|---:|---:|---:|---:|
| 100 | 704.192 | 1,039.068 | 1,042.011 | 37.624 |
| 200 | 792.454 | 928.713 | 952.066 | 41.858 |
| 300 | 961.683 | 1,013.159 | 1,023.447 | 50.859 |

三个训练随机数的原始状态和门控状态全部有限，单个记忆状态分量绝对值最大为`119.4891`。
训练随机数100第一确认批次的平均原始记忆状态范数为`1,024.387`，与保存的运行诊断一致。

事实边界：

- 大范数不是单个异常样本造成；
- 现有产物没有证明它导致性能下降、梯度爆炸或预测爆炸；
- 版本08的历史门置零诊断只能证明共同训练后的模型使用历史初始状态，不能证明历史气象的
  因果贡献；
- “遗忘门偏置5.0与120个历史时间步造成累积”是结构解释，不是已被单因素实验验证的事实。

## 2. 版本09当前机制和监测缺口

版本09连续历史候选仍使用：

- 120个历史时间块；
- 256个历史长短期记忆网络单元；
- 256个近期长短期记忆网络单元；
- 初始遗忘门偏置5.0；
- 分别对历史隐藏状态和记忆状态使用从精确零开始学习的逐元素双曲正切门；
- 门控后的两个状态用于初始化270天近期路径。

由当前计算图可推出：

1. 第一次反向传播时，门值为零，历史编码器参数梯度应为精确零；
2. 同一步的门参数仍可接收来自近期路径的梯度；
3. 第一次参数更新使门离开零后，历史编码器应在后续更新中收到梯度。

现有训练计划已经要求连续历史候选在第3次更新前出现非零有限的历史编码器梯度，但只规定
非有限值和梯度链路停止，没有冻结全流域状态分布、门饱和程度及其独立重放证据。这是正式预测
前必须补齐的可审计性缺口。

## 3. 不改变训练轨迹的诊断设计

### 3.0 先冻结确定性运行环境

版本09实现训练入口前，必须先在两个全新进程中通过正式图形处理器确定性预检。两个进程使用
相同合成输入、模型参数、批量大小和120步历史序列，分别执行历史编码器前向和状态诊断，输出
张量必须逐字节相同。运行环境固定并封存：

- 在导入PyTorch前设置`CUBLAS_WORKSPACE_CONFIG=:4096:8`；
- 启用`torch.use_deterministic_algorithms(True)`；
- 设置`torch.backends.cudnn.benchmark=False`和
  `torch.backends.cudnn.deterministic=True`；
- 禁用矩阵乘法和卷积的TensorFloat-32快速路径；
- 记录PyTorch、CUDA、cuDNN、图形处理器、驱动和上述全部开关。

若当前硬件或软件不支持这些确定性设置，或两个全新进程的状态数组哈希不同，固定结论为
`NO-GO`训练。不得把状态重放从完全相同放宽为近似相同，也不得静默更换设备或算法。

### 3.1 训练中只记录同一次反向传播产生的健康信息

训练器不得为了状态诊断增加第二次模型前向。它只从正式训练已有的计算图和梯度中记录：

- 第1次更新前两个历史门严格为零；
- 第1次反向传播的全部历史编码器梯度存在、有限且逐元素为零；
- 第1次反向传播的两个门梯度存在且有限，两个门梯度的合并欧氏范数严格大于零；
- 第3次更新结束前，历史编码器至少一次出现严格大于零的有限梯度欧氏范数；
- 每轮历史编码器非零梯度更新计数；
- 每轮两个门参数及门梯度的欧氏范数和最大绝对值；
- 每轮预测、损失、裁剪前后梯度、参数及Adam优化器状态的有限性。

这些字段只判断计算图是否按预注册结构工作，不包含验证指标、正式期预测或候选优劣。

### 3.2 训练完成后使用独立进程计算状态分布

24次主训练全部完成后、任何正式期预测之前，单独的只读诊断进程只加载：

- 已封存的Maurer训练期气象输入；
- 27项静态属性；
- 连续历史候选的第10、20、30轮检查点；
- 冻结的流域顺序、训练日期顺序、分箱规则和版本09诊断源码。

该进程不得打开训练目标数组、正式评估期观测、旧测试结果、评分答案或评分服务，也不得执行
近期路径、流量输出头或生成流量预测。

固定诊断面板包含全部531个流域和每个流域12个训练日期，共6,372个样本。日期索引由
`floor(linspace(0, 3287, 12))`预先固定：

| 日期索引 | 日期 |
|---:|---|
| 0 | 1999-10-01 |
| 298 | 2000-07-25 |
| 597 | 2001-05-20 |
| 896 | 2002-03-15 |
| 1,195 | 2003-01-08 |
| 1,494 | 2003-11-03 |
| 1,792 | 2004-08-27 |
| 2,091 | 2005-06-22 |
| 2,390 | 2006-04-17 |
| 2,689 | 2007-02-10 |
| 2,988 | 2007-12-06 |

面板顺序固定为流域主序：先按冻结531流域顺序，再按上表日期索引升序。全部训练键同样先按
冻结流域顺序，再按日期索引0至3,287排列。

每个第10、20、30轮检查点都计算该固定面板；第30轮还按冻结流域顺序、再按训练日期顺序计算
全部1,745,928个训练键。每个样本保存以下五个`float32`值：

1. 256维原始历史隐藏状态的欧氏范数；
2. 256维原始历史记忆状态的欧氏范数；
3. 256维门控后历史隐藏状态的欧氏范数；
4. 256维门控后历史记忆状态的欧氏范数；
5. 原始历史记忆状态分量的最大绝对值。

状态数组固定为C连续、小端`float32`、形状`[样本数, 5]`；键数组固定为C连续、小端
`int32`、形状`[样本数, 2]`，两列依次为冻结流域索引和训练日期索引。清单同时登记数组C连续
原始字节和`.npy`文件的SHA-256。

每个检查点另保存：

- 两个门参数的欧氏范数、最大绝对值；
- `abs(tanh(gate)) >= 0.95`的参数比例，作为饱和描述；
- 每列的最小值、中位数、95%分位、99%分位和最大值；
- 样本键字节流、五列状态数组、输入、检查点、源码和环境的SHA-256；
- 有限值计数和非有限值位置。

状态数组必须写入训练运行目录之外的独立目录：

```text

  E09-CONTINUOUS_s100/
  ...
  E09-CONTINUOUS_s800/
```

每个随机数目录至少包含：

- `epoch010_panel_keys.int32.npy`
- `epoch010_panel_state_norms.float32.npy`
- `epoch020_panel_keys.int32.npy`
- `epoch020_panel_state_norms.float32.npy`
- `epoch030_panel_keys.int32.npy`
- `epoch030_panel_state_norms.float32.npy`
- `epoch030_all_training_keys.int32.npy`
- `epoch030_all_training_state_norms.float32.npy`
- `summary.json`
- `manifest.json`

已封存的24个训练运行目录不得因诊断而修改。

汇总统一把保存的`float32`数组转换为`float64`，分位数固定使用NumPy的线性插值方法。汇总
JSON只来自已落盘并重新加载的状态数组，不能直接使用运行中临时值。

### 3.3 独立重放

第二个只读进程在相同正式设备和环境上重新加载输入与检查点，使用相同批量顺序重算全部诊断。
独立审核报告位于状态诊断目录之外：

```text
results/26_historical_band_experts/formal_v09/state_diagnostics_external_audit.json
```

只有八个连续历史候选的全部状态数组、键顺序和汇总均通过后，状态诊断报告才能被训练总封存绑定。

## 4. 复现容差

| 比较对象 | 容差 |
|---|---|
| 同进程严格嵌套的预测、损失、梯度、参数和Adam状态 | 绝对容差0、相对容差0 |
| 冻结经典检查点在核心模型、版本09经典模型和停用历史模型上的同设备前向 | 绝对容差0、相对容差0 |
| 独立进程训练期预测重放与封存数组 | 最大绝对差不超过`1e-6`、相对容差0 |
| 同检查点、同输入、同设备、同环境的状态诊断独立重放 | 样本键和五列`float32`数组SHA-256完全相同 |
| 由相同状态数组计算的汇总 | `float64`重算值逐元素完全相同 |
| 中央处理器与图形处理器之间的状态范数 | 不作数值相等声明，只分别要求有限并记录环境 |

实现前的合成测试还必须证明：启用或停用训练中健康信息记录后，预测、损失、裁剪前后梯度、
参数、Adam状态、Python随机数状态、NumPy随机数状态、PyTorch中央处理器随机数状态和全部
图形处理器随机数状态逐元素或逐字节完全相同。若不相同，不能启动正式训练。

## 5. 停止条件与报告条件

以下任一情况固定停止训练阶段并标记`HOLD`，不得进入正式预测：

- 第1次更新的零门、历史编码器零梯度或门梯度条件不成立；
- 第3次更新结束前没有非零有限的历史编码器梯度；
- 预测、损失、任一状态、梯度、参数或Adam状态出现非有限值；
- 状态诊断读取了训练目标、正式评估观测、正式期流量答案或评分服务；
- 6,372个固定面板样本或1,745,928个第30轮训练样本覆盖不完整、重复或顺序漂移；
- 诊断数组、键、检查点、输入、源码或环境哈希漂移；
- 正式图形处理器确定性预检失败，或运行时确定性开关与预检不一致；
- 同设备独立重放的状态数组SHA-256不一致；
- 诊断健康信息改变了正式训练的随机数或优化轨迹；
- 内存、显存、单次分配、原子写入或目录隔离规则不满足。

以下情况必须报告，但不是停止、选择或调参条件：

- 任意有限的原始或门控状态范数，包括超过版本08的最大值；
- 任意有限的单个状态分量；
- 任意有限的门参数范数；
- 任意门饱和比例；
- 八个训练随机数之间的有限状态分布差异。

不能用版本08的`704.192`、`1,039.068`或`1,042.011`设置版本09事后阈值。这些数值来自不同
窗口上限和内部确认样本，只提供风险背景，不是正式版本09的自然上限。

## 6. 推荐方案

推荐保留已内部通过的连续历史候选，增加上述独立状态诊断，不在版本09中加入记忆状态裁剪、
归一化、遗忘门偏置调整或新门控结构。原因是这些修改会改变已经预注册的候选，不能再称为同一
模型的531流域确认。

如果版本09出现非有限状态或梯度链路失败，正式流程停止。如果状态始终有限但偏大，则如实报告，
并由一次性正式评分决定预注册性能结论。任何稳定化改造只能作为新的实验家族，重新经过内部
筛选、容量控制、严格嵌套和独立审核，不能用于挽救或改写版本09结果。
