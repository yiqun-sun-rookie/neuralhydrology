## 正式评分服务的实际行为

事实：

- `score.py`通过`tracks.py::load_track`直接读取规范文件；
- `tracks.py`要求`confirmed: true`，并从规范读取基准、秘密流域、答案文件和门槛；
- `score.py`和`tracks.py`都不读取或验证`MANIFEST.sha256`；
- 正式门还由`gate.py`实施：
  配对中位提升至少0.01、Wilcoxon检验p值小于0.05、自助抽样区间下界大于0、
  秘密流域提升至少0.005，并保留至少50%的公开提升；
- `stats.py`固定使用随机数0进行10,000次流域自助抽样。

推断：

冻结清单不一致不会自动阻止评分程序运行，反而意味着必须由外层前置审核阻止未经处置的调用。
仅仅“评分程序能够运行”不能证明冻结来源完整。

## 推荐的非破坏性处置

正式评分前另行实现并审核一个外层只读前置门；它不修改冻结目录和评分代码。
前置门必须同时验证：

1. 当前代码提交和工作区干净；
2. 冻结目录及正式评分代码相对版本09实施父提交没有差异；
3. 规范文件 Git 对象标识为`cde74e4a...`；
4. Git 文件内容 SHA-256 为`0439eb55...`；
5. 工作区字节只允许 Git 换行版本`0439eb55...`或已记录的 Windows 换行版本
   `8fb707cb...`，并记录操作系统和换行形式；
6. 语义 SHA-256 为`dedf11d4...`；
7. `score.py`、`tracks.py`、`gate.py`、`stats.py`和`ledger.py`各自的文件哈希已封存；
8. 正式预测的唯一哈希、531流域完整覆盖和每流域3,652个日期已通过；
9. 正式评分实验标识此前没有账本记录；
10. 用户的单独评分授权凭据逐字承认冻结清单的历史不一致，并只授权一个预测哈希的一次调用。

评分调用一旦启动即消耗该授权。无论程序通过、暂缓、拒绝或异常退出，都不得凭原授权重试。

## 停止条件

以下任一情况成立时，正式评分继续保持不允许：

- 用户没有单独批准上述历史例外和唯一预测哈希；
- Git对象、实际字节、语义指纹或评分代码任一哈希漂移；
- 冻结目录或评分代码有改动；
- 正式预测未完成独立审核；
- 同一正式评分实验标识已有账本记录；
- 输入、训练、预测或最终独立审核的前置阶段未通过。
