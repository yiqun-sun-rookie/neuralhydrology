# 历史连续多尺度气象模型版本09核心经典控制修复

## 结论

版本09原实现不能复现真实核心经典长短期记忆网络的训练计算，原因是原实现只对最后隐藏状态使用按批次生成的丢弃，而核心 `CudaLSTM` 对完整近期状态序列使用标准 PyTorch 丢弃。该偏差已修复。修复后的合成测试以零容差匹配核心模型的参数初值、同一位置张量的输入拼接、训练预测、随机数状态、损失、梯度、梯度裁剪、Adam状态和更新后参数。

这只是模型与优化计算的兼容性结论。版本09采用仅训练期统计，旧模型的数据统计边界不同，因此目前不能声称复现旧检查点、旧完整训练轨迹或中位纳什－萨特克利夫效率系数 `0.759225`。

后续只读审核进一步确认：上述合成测试把同一个随机静态张量交给两条路径，因此没有证明真实27项静态
属性的名字到张量位置映射。旧核心数据集实际在归一化和张量化前按列名字母排序；正式版本09输入计划
必须显式采用相同字母顺序，并以`ddof=1`计算静态尺度。该修正不改变已通过的模型函数桥接结论，但
是把真实输入语义对齐经典路径的必要条件。正式训练前的旧检查点桥接门现另要求在531个流域、
每流域12个固定训练日期的6,372个真实Maurer与静态属性样本上重复三路径零差异；该门尚未执行。

同一延伸审核还确认精度顺序必须对齐：旧核心用源双精度静态属性计算统计并归一化，最后才转
`float32`。若先转`float32`再计算，14,337个静态值中有8,421个归一化结果位不同，最大绝对差
`8.344650268554688e-7`。正式输入现要求封存预归一化静态有效载荷哈希
`aa53d1d06247b246f5557efe6761b9b7becd2be3a680f99d667d2e3c89b9b37a`。

## 1. 发现的问题

只读审核固定到实际运行配置记录的核心代码提交 `1f9804e359283f1963bcf0aa9ffab213538c16e8`，并检查真实运行配置、核心 `CudaLSTM`、输入层和回归输出头。当前跟踪的种子100配置直到提交 `49433803a6a598fde068f732834e6f918ee826f4` 才进入仓库，因此它是可移植测试快照，不是假称存在于原训练提交中的文件。修复前的同一合成批次结果为：

- 参数量：两者均为297,217；
- 参数初值：逐元素相同；
- 输入拼接：逐元素相同；
- 评估模式预测最大绝对差：`0`；
- 训练模式预测最大绝对差：`0.4232901632785797`；
- 前向后的随机数状态：不相同。

因此，原实现只能说明无丢弃时的前向结构相同，不能支持“严格复现经典训练”的结论。

## 2. 修复内容

- 新增核心兼容经典近期模型：单层、32输入、256隐藏、270天窗口和单流量输出；
- 采用与核心模型相同的模块构造顺序和参数命名；
- 对完整近期状态序列应用比例0.4的标准 PyTorch 丢弃，再应用回归输出头；
- 损失只读取最后一个时间步，与经典配置 `predict_last_n: 1` 一致；
- 禁用历史的嵌套模型在隔离随机数作用域内构造历史模块，不改变活跃近期路径的初值或构造后的随机数状态；
- 严格嵌套比较新增前向后随机数状态相等检查；
- 协议冻结核心参考文件的统一换行哈希。

## 4. 验证范围和停止条件

修复后的核心兼容、模型、嵌套、协议和旧参考验证专项共19项，全部通过。真实旧参考只读验证覆盖8个运行、16个文件，配置哈希、检查点哈希、配置内随机数和提交前缀全部一致。完整测试套件仍须满足12.68 GiB长任务启动线后才能运行。

继续验证必须满足：

1. 可用物理内存回到8 GiB以上才运行轻量专项；
2. 可用物理内存至少12.68 GiB才运行完整套件或任何长任务；
3. 同一进程的最大绝对和相对容差均为零；
4. 独立环境最终预测最大绝对差不超过 `1e-6`，相对容差为零；
5. 任一参数、随机数状态、预测、损失、梯度、优化器状态或更新参数不相等，立即停止；
6. 正式目标生成、训练、正式预测和评分仍未授权。
