# 历史连续多尺度气象模型正式版本09留出集合复用审计

## 结论

原`track0_forcing_only`的107流域留出集合不能继续被称为未触碰的秘密留出集，也不能承担正式
版本09的独立留出门。真实账本已经记录7次使用同一424/107划分的评分，主仓库保留的6份报告均
公开了该留出集的聚合结果，研究总结还用这些结果解释后续模型表现。

这不证明正式版本09候选读取过逐流域留出答案；截至本审计，正式版本09没有生成正式预测，也没有
调用评分服务。受影响的是留出集合的全局独立性声明，不是版本09候选现有内部结果的输入合法性。

正式版本09当前状态为`HOLD`。推荐修复是：清洁经典近期模型、同参数量控制和连续历史候选的三个
八随机数集合全部封存后，唯一评分进程先独占消费一次性授权，再从操作系统密码学随机源抽取一次
256位随机数，与三组预测哈希共同派生新的107流域集合；其余424流域作为公开比较集。随机数不得
预生成、挑选或重抽，任何中断均不得重试。

## 推断

原107流域集合的聚合结果已经多次进入研究反馈，因此继续把它称为“秘密且独立”会高估其抗选择
能力。即使正式版本09的模型路线来自独立的60流域内部筛选，原留出集也只能作为历史诊断，不能
恢复为新的独立确认集。

先封存全部预测，再由唯一评分进程一次抽取随机数，可以切断“看到留出划分后修改预测”的反馈链。
随机数与三组预测哈希共同进入划分预映像，确保任何预测字节变化都会改变评分身份并使原授权失效。

## 未知

- 目前无法确定7次账本评分之外是否还有未登记的临时评分调用。
- 目前无法确定旧留出聚合反馈对任何既有模型设计造成了多大数值影响。
- 新107流域集合在正式评分前未知；其结果也不能提前估计。

这些未知不改变当前`HOLD`，也不构成读取正式观测或追加一次试评分的理由。

## 必须满足的停止条件

- 未获得清洁同信息配对路线的精确批准：停止，不写评分实现。
- 三组预测未全部封存或任一哈希漂移：停止，不抽取留出随机数。
- 一次性评分授权未独占消费：停止，不抽取留出随机数。
- 消费收据、随机数抽取收据或正式报告已存在：停止，不重抽、不重试。
- 可用物理内存低于12.68 GiB：停止，不运行完整测试或正式评分。
- 正式答案、冻结边界、账本链或源码哈希漂移：停止，不评分。
