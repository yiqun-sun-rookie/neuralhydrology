## 数值读取时序的准确解释

“没有提前读取主结果数值”不等于“完全不接触主结果文件”。复现开始前会读取清单、校验文件，并顺序读取主结果归档的原始字节来计算校验值。这一步只证明文件没有变化，不会把数组解码成数值。真正的数值访问发生在独立重算数组已经保存之后，由精确比较函数同时打开主结果归档和重算归档，逐个检查 36 个数组的名称、数据类型、形状和所有元素。

因此，当前实现满足的标准是：主结果可用于身份校验和事后精确比较，但不能为重算提供数值、初始状态或失败重用数组。

## 原子发布边界

代码对可处理异常的闭包顺序是充分的：内容验证、资源结束、文件校验、临时目录闭包检查、原子改名、登记为“已验证”、已发布目录闭包检查。单流域的结果目录和日志目录无法跨两个目录形成一次操作系统级的共同原子事务，但登记放在两次原子改名之后，聚合又要求登记终态和两个目录校验值同时正确，所以中间状态不能成为聚合输入。

本审查没有强制关闭电源或杀死操作系统进程；硬中断结论来自固定调用顺序和每个中间状态的验证条件。该限制不阻断当前代码放行。

## 不得越界的结论

本报告只证明当前代码具备安全执行正式复现的条件。它没有产生新的 16 个流域结果，也没有验证新的聚合指标、不同提前时间效果、参数权重或噪声权重。只有以下条件全部满足后，才能把科学复现状态改为“完成”：

1. 16 个正式流域分别生成状态为“已验证”的新结果和日志包；
2. 每个流域恰好 36 个数组、366960 个数值，并与冻结主结果逐值完全相等；
3. 聚合包恰好包含 576 个数组、5871360 个数值；
4. 聚合指标、表格、图片和报告通过独立重算；
5. 结果、日志、资源记录和登记校验值全部闭合。

处理器负载会被记录，数值线程被限制为 1 个，但代码没有按处理器负载百分比自动停止。正式执行时应一次只运行一个流域片；在其他任务占用处理器或内存时等待，避免多个独立进程同时通过启动检查后争用资源。
